# Nora: дизайн и архитектура

[English](../en/DESIGN.md) · [Українська](../uk/DESIGN.md) · 🇷🇺 Русский

> **Nora** (укр. *нора* — жилище крота) — утверждённое название. Название «Mole» сторонним проектам использовать нельзя (`TRADEMARK.md` в Mole), а «Burrow» уже занято прямым конкурентом.
> Интерактивный прототип: [`prototype/`](../../prototype/) (онлайн: https://lexus2016.github.io/Nora/prototype/). Данные в нём демонстрационные, но все форматы повторяют реальный вывод Mole 1.59.1.

## 0. Коротко

- **Стек:** нативный SwiftUI + AppKit, macOS 14+. Mole работает только на macOS, а оба сильнейших референса (MangelSP/MoleUI, Burrow) нативные. Tauri-обёртки проигрывают и по ощущению, и по безопасности (`csp: null`, смешанные stdout/stderr).
- **Mole не встраиваем.** Nora находит его, предлагает установить и обновляет через канал пользователя. Так нет обязательств по распространению GPL и не ломается обновление.
- **Сама устанавливает и обновляет Mole:** Homebrew или официальный установщик Mole фиксированной версии с проверкой суммы в `~/.local/bin`, без Терминала и пароля администратора. **Обновляется сама** через Sparkle 2.
- **Меню быстрого доступа в строке меню:** живые показатели системы, место, которое можно освободить, переход в любой раздел, состояние и обновление Mole. Блок «Больше всего нагружают» переключается между «Память» (давление, занято / кеш / свободно, swap, топ-3 программы, где процессы-помощники отнесены к своей программе) и «Процессор». По решению владельца (13.10.2026) блок только показывает, куда уходит память, и ничего не освобождает, не закрывает и не завершает. Сам Mole память не освобождает: очистку swap в нём убрали как риск сбоя. В меню четыре плитки показателей: по умолчанию CPU, память, сеть и диск; в Настройках можно выбрать любые четыре из CPU, памяти, сети, диска, графики и вентилятора (решение владельца, 13.10.2026). Остальное — на странице «Состояние системы».
- **Машинный интерфейс Mole неполный.** JSON отдают `status`, `analyze`, `history` и `uninstall --list`; остальное — текст и TUI-запросы. Поэтому слой интеграции работает в трёх режимах: JSON-pipe, NDJSON-поток и PTY с автоответчиком.
- **Главный принцип:** чекбокс появляется только там, где известно, как Mole выполнит выбор. Механизм каждого выбора назван в §4. Ни одна из четырёх обёрток-референсов этого не соблюдает.
- **Дизайн:** структура CleanMyMac. У каждого модуля своя сцена с большим стеклянным 3D-объектом, коротким описанием и круглой кнопкой «Сканировать». Палитра неоновая, в духе Hotline Miami. Интерфейс простой: «Сканировать → Просмотр → Готово», а сложное спрятано в консоль и «Инструменты».

Важные факты из кода:
- В `mo clean` **нет выбора отдельных позиций**: `--select/--categories/--exclude` удалены (`bin/clean.sh:2116`).
- **Ловушка whitelist:** пока файла `~/.config/mole/whitelist` нет, действуют 13 стандартных защит (`lib/core/base.sh:168`: `~/.ollama/models`, Gradle, JetBrains, Playwright, iCloud…). Любой записанный файл их **заменяет** (`lib/manage/whitelist.sh:206`). Обязательные правила безопасности (FontRegistry, Spotlight, CloudKit…) добавляются всегда.
- `clean` и `purge` удаляют **безвозвратно** (`safe_remove`, варианта с Корзиной нет). `installer` по умолчанию удаляет безвозвратно, но учитывает недокументированную `MOLE_DELETE_MODE=trash` (`installer.sh` → `mole_delete`), которую задаёт Nora. `uninstall` — в Корзину, если не указан `--permanent`.
- sudo привязан к TTY: `adopt_sudo_session` использует `sudo -n`. Без TTY Mole показывает собственный диалог через osascript (`lib/core/sudo.sh:95`).
- `MOLE_PRESELECTED_INDICES` учитывают `menu_paginated`/`menu_simple` (выбор программ), но не меню `installer`.
- Журнал операций: `~/Library/Logs/mole/operations.log`.

## 2. Референсы-обёртки

| | MangelSP/MoleUI | Zhili1004/MoleUI | gokuscraper/mole-gui | caezium/Burrow |
|---|---|---|---|---|
| Стек | SwiftUI, macOS 14, SwiftTerm | Tauri 2 + чистый JS | Tauri 2 + React 19 | SwiftUI; собственный Rust-движок, совместимый с Mole |
| Mole | системный `mo` | встроенный 1.42 | системный `mo` | встроенный движок |
| Сильное | строка меню, встроенный терминал, уведомления по порогам, процессы/порты/сеть/вентилятор | разбор clean-list, askpass + PTY, редакторы whitelist | концепция Smart Care, цвета модулей | treemap, история метрик в SQLite, MCP-сервер, Sparkle, вкладка обновлений |
| Слабое | обслуживание без выбора; завершение процессов без подтверждения; одно отсутствующее поле JSON «гасит» дашборд; «Abort» не завершает процесс | `uninstall </dev/null` → «Aborted», а GUI пишет «удалено»; installer удаляет всё; `csp: null` | чекбоксы ничего не делают; коды выхода игнорируются; stderr ломает JSON; нет sudo | прямой конкурент; название занято |

**Берём:**
- у MangelSP: архитектуру SwiftUI, SwiftTerm как запасной терминал, строку меню, уведомления;
- у Zhili: разбор clean-list и идею блока-маркера в whitelist (с исправлением ловушки стандартных защит), askpass в PTY;
- у gokuscraper: «Умный уход»;
- у Burrow: долгую историю метрик, MCP только на чтение, подписанные обновления, treemap;
- у CleanMyMac (ваши скриншоты): структуру экрана модуля, стеклянные 3D-объекты, круглую кнопку, панель «Работа выполнена!» и «Историю активности».

**Не берём:** встраивание Mole, веб-стек, «слепые» нажатия клавиш без сверки экрана, действия без подтверждения, `curl | bash`, скрытый от пользователя.

### 4.3. За пределами Mole (утверждено 13.10.2026)

Отдельный раздел в боковой панели есть только у «Безопасности», и он уже существует. Остальное встраивается в имеющиеся экраны:
- **«Безопасность»** с антивирусной проверкой (§4.4).
- **Обновления программ** в «Программах»: фильтр «Обновления» показывает устаревшие программы Homebrew (`brew outdated --cask`) и обновляет выбранные (`brew upgrade --cask <имя>`). Только программы Homebrew; программы из App Store и обновляющиеся сами не охватываем.
- **Энергия и температура** в «Состоянии системы», только показ: ватты CPU/GPU и температуры Apple silicon без пароля, как в macmon. Опирается на недокументированный API IOReport; если он сломается, карточки покажут «недоступно», а не неверные числа.
- **Режим энергии** в «Состоянии системы»: Тихо / Авто / Мощно, тот же переключатель, что и в Системных настройках → Аккумулятор → Режим энергии (`pmset -a powermode` или `lowpowermode`, как в MangelSP). «Мощно» появляется только там, где у Mac есть ключ `powermode`. Каждое изменение спрашивает пароль или Touch ID через `sudo -A`.
- **Порты и сеть** в «Состоянии системы», только показ: кто слушает порты и сколько трафика берёт каждая программа, как в MangelSP. Без завершения процессов.
- **Отклонено:** прямое управление вентилятором через SMC (нужен привилегированный помощник; на Apple silicon вентиляторами управляет прошивка) и менеджер процессов (решение по памяти от 13.10.2026).

**Модуль «Безопасность»** (в плане M5; подход выбран после анализа MacSai):
- аудит автозапуска только на чтение: LaunchAgents/LaunchDaemons, Login Items, расширения браузеров;
- для каждого элемента — проверка подписи, Gatekeeper и нотаризации через `Security.framework` (`SecStaticCodeCheckValidity`, `SecAssessment`) с объяснением каждой находки;
- правила самой Apple из локального `XProtect.yara` через `yara` (без распространения) и движок ClamAV как внешний `clamd`/`clamscan` (GPLv2 остаётся вне приложения), устанавливается и обновляется по запросу;
- находки никогда не отмечаются автоматически; загруженный агент выгружается (`launchctl bootout`) до переноса файла в карантин или Корзину, после подтверждения;
- проверку можно называть антивирусной, но без обещаний полной защиты в реальном времени и никогда «вирусов нет».

### 4.4. Дизайн модуля «Безопасность» (ClamAV + Apple XProtect + нативный аудит)

Исследовано 13.10.2026. Пункты с пометкой *проверить* тестируются в спайке M5 до выпуска.

- **Позиционирование.** Антивирусная проверка по запросу и по расписанию, плюс проверка «Загрузок», которую включает пользователь. **Полной защиты в реальном времени нет:** сканирование при доступе в ClamAV есть только в Linux, а Endpoint Security требует разрешения Apple и системного расширения. В интерфейсе — «сигналы для просмотра», никогда «вирусов нет» или «защищено». Находки никогда не отмечаются автоматически.
- **Конвейер:**
  1. **Нативный аудит.** LaunchAgents/LaunchDaemons, объекты входа и фоновые элементы (BTM), профили конфигурации, расширения браузеров. Подпись проверяется через `SecStaticCodeCheckValidity` с `kSecCSCheckAllArchitectures`, нотаризация — через `spctl -a -vv` (`source=Notarized Developer ID`), а также xattr карантина. У каждой находки есть объяснение.
  2. **Правила Apple XProtect.** `yara` 4.5.8 (BSD-3) прогоняет локальный `XProtect.yara` (≈1 МБ, 506 правил), который читается во время работы и никогда не копируется и не встраивается. *Проверить*, что он компилируется стандартной yara.
  3. **ClamAV 1.5.4** (GPLv2, Homebrew; формула заодно ставит yara). На время сканирования Nora запускает `clamd --foreground` дочерним процессом, сканирует через `clamdscan --fdpass` и затем останавливает его, так что ни один постоянный процесс не держит 1,2 ГБ и больше памяти, если не включена проверка «Загрузок». `freshclam` запускается не чаще раза в сутки, есть ручное «Обновить сейчас» и пауза при HTTP 429. Базы занимают ≈107 МБ (main 85 МиБ, daily 22 МиБ). Свои конфиги Nora хранит в `~/Library/Application Support/Nora/clamav`. *Проверить*, что дочерний процесс наследует полный доступ к диску.
  4. **Опциональная репутация хешей.** Только с согласия, только SHA-256 и только для файлов, у которых уже есть находка: CIRCL hashlookup отсеивает известные безопасные файлы, MalwareBazaar или VirusTotal работают с собственным ключом пользователя.
- **Объёмы.** «Быстрая» проверка охватывает автозапуск, цели BTM, `/Applications`, Загрузки и Рабочий стол. «Полная» — `$HOME` без незагруженных файлов iCloud/CloudStorage, а число пропущенного показывается.
- **Расписание и проверка «Загрузок».** Оба по умолчанию выключены и включаются в Настройках. Расписание запускает быструю или полную проверку ежедневно или еженедельно. Проверка «Загрузок» следит за `~/Downloads` через FSEvents и проверяет каждый новый файл, как только он докачался (без суффиксов `.download`, `.crdownload`, `.part`, размер больше не меняется). Пока она включена, `clamd` работает постоянно: около 1 ГиБ памяти и до 2,4 ГиБ во время ежедневного обновления базы (документация ClamAV). Настройки показывают это рядом с переключателем. Находка отправляет уведомление, а файл уходит в карантин только после подтверждения.
- **Карантин.** `~/Library/Application Support/Nora/Quarantine/<uuid>/` содержит файл и `meta.json` (SHA-256, исходный путь, владелец, права, xattr, имя правила или детекта). Восстановление — один клик; окончательное удаление — отдельное действие с подтверждением. Загруженный агент сначала выгружается (`launchctl bootout gui/$UID/<label>`). Элементы с подписью Apple, `/System` и `/usr` никогда не трогаются.
- **Лицензии.** `libclamav` никогда не линкуем, ClamAV запускаем только отдельными процессами. Не встраиваем базы ClamAV, правила XProtect и правила под Elastic License. Сторонние наборы (signature-base DRL-1.1, пакеты YARA Forge) не берём, пока не проверена лицензия каждого правила.
- **Чего не делаем.** Никаких «сигнатур» по подстрокам имён (как в MacSai), никакого автоисправления, никакой автоматической отправки файлов наружу, никаких вшитых API-ключей.

## 5. Архитектура

```
Nora.app (SwiftUI, macOS 14+)
├─ Сцены: главное окно · пункт строки меню (NSStatusItem + NSPopover) · Settings
├─ Модули: SmartCare, Clean, Apps, Speed, SpaceMap, Status, Projects, Installers, Protect, History, Tools, Security
└─ MoleKit (Swift package, без UI)
   ├─ Locator          zsh -lc 'command -v mo', /opt/homebrew/bin, /usr/local/bin, ~/.local/bin, ~/.mole/mo, Nix; ручной путь
   ├─ Capabilities     --version + `<cmd> --help` → карта флагов; минимум 1.55
   ├─ ProcessRunner    pipe-режим: раздельные stdout/stderr, коды выхода, SIGINT → SIGTERM
   ├─ NDJSONStream     status --watch; терпимый Decodable
   ├─ PTYSession       forkpty; удаление ANSI; PromptResponder (правила + сверка ожидаемого экрана)
   ├─ Parsers          clean-list, optimize, purge, installer; эталонные фикстуры для каждой версии Mole
   ├─ WhitelistOverlay транзакция + журнал + восстановление после сбоя
   ├─ PrivilegeBroker  SUDO_ASKPASS-хелпер с нативным диалогом / Touch ID; пароль никогда не сохраняется
   ├─ MoleInstaller    brew install mole или официальный install.sh фиксированной версии с проверкой суммы → ~/.local/bin
   ├─ MoleUpdater      сравнение mo --version с GitHub Releases; обновление через канал установки
   ├─ HistoryStore     SQLite: сэмплы метрик + разобранная история Mole
   └─ Scheduler        SMAppService/launchd: проверки только для просмотра
```

Инварианты безопасности:
1. Ни одного разрушительного действия без просмотра и подтверждения.
2. PTY отвечает «да» только после совпадения превью с выбором.
3. Whitelist всегда возвращается в исходное состояние.
4. Точная команда видна перед каждым действием.
5. Коды выхода и stderr не теряются.

Тесты: парсеры на фикстурах реальных запусков (CI-матрица с `brew install mole`), интеграционные тесты в отдельном `$HOME`, snapshot-тесты UI.

### 6.1. Навигация: не больше трёх кликов

Любое действие — максимум в трёх кликах от открытия Nora или строки меню, и с каждого шага легко вернуться назад (решение владельца 13.10.2026).

- **Экран проверки и есть подтверждение.** Кнопка «Очистить / Удалить» на нём выполняет действие сразу, без второго диалога «Вы уверены?». Список, размеры, команда и предупреждение об окончательном удалении уже на экране, а во время работы доступны «Стоп» и консоль. **Одно исключение** (решение владельца, 13.10.2026): когда пользователь выбирает «Удалить безвозвратно» для программ, Nora переспрашивает ещё раз. Остальное диалога не требует: установщики и программы уходят в Корзину, а кэши, журналы и файлы сборки программы и сборки создадут заново. Fixture-тест для каждой поддерживаемой версии Mole проверяет, что `MOLE_DELETE_MODE=trash` по-прежнему ведёт в Корзину; если нет, «Установщики» удаляют безвозвратно и говорят об этом на экране проверки.
- **«Программы»** открываются сразу списком: `mo uninstall --list` только читает и работает быстро.
- **Плитки Умного ухода** ведут сразу на экран проверки модуля, без повторного сканирования.
- **Назад:** стрелка ← в заголовке каждого шага после стартового, а также Esc и ⌘[. Если шаг открыт из другого места (плитка, строка меню), «Назад» возвращает туда. Боковая панель всегда в одном клике.

| Действие | Путь | Кликов |
|---|---|---|
| Очистить всё безопасное | Сканировать → Запустить | 2 |
| То же из строки меню | значок → Очистить → Запустить | 3 |
| Очистка с выбором | Очистка → Сканировать → Очистить | 3 |
| Удалить программу | Программы → ☑ программа → Удалить | 3 (+1 для «Удалить безвозвратно») |
| Установщики / артефакты проектов | Сканировать → плитка → Удалить | 3 |
| Обслуживание | Быстродействие → Сканировать → Запустить | 3 |
| Файл из Анализа диска в Корзину | Анализ диска → Сканировать → элемент → В Корзину | 3 + глубина папки |

## 7. Прототип

`prototype/index.html` + `app.js` + `assets/glass/`. Онлайн: https://lexus2016.github.io/Nora/prototype/. Локально: `cd prototype && python3 -m http.server 8000` → http://localhost:8000.
- Все экраны и полные сценарии (сканирование → просмотр → запуск → «Работа выполнена!») для Умного ухода, Очистки, Программ, Быстродействия, Проектов, Установщиков и Безопасности.
- «Сценарії» вверху: Mole отсутствует / устарел, нет полного доступа к диску, есть сессия sudo.
- **Язык:** приложение показывает английский, украинский или русский автоматически по языку системы; для любого другого языка — английский. Переключателя языка нет. Прототип в браузере открывается на английском; `?lang=uk|ru` показывает два других (ими сняты скриншоты README). Строки приложения лежат в `App/Localization` (английские ключи, `uk.json` и `ru.json`), а `python3 scripts/l10n.py extract` показывает строки без перевода. Текст прототипа украинский, с `prototype/i18n-en.js` и `i18n-ru.js`; его проверяет `python3 scripts/i18n_check.py`.

### 8.1. Состояние сборки (15.10.2026): текущий выпуск 1.2.0

Приложение впервые выпущено как 1.0.0 14.10.2026; текущий выпуск 1.2.0, в GitHub Releases с обновлениями Sparkle через `appcast.xml` на GitHub Pages. Оно собрано (`App/`, SwiftUI, XcodeGen). Оно выходит как DMG, подписанный Developer ID, прошедший нотаризацию и со вшитой квитанцией, через `scripts/build-dmg.sh` (см. `docs/BUILD.md`). Каждый модуль в боковой панели запускает настоящие команды Mole; макетов нет.

Отклонения от этого дизайна, на ваше вето:
1. **Выбор в «Проектах»** работает через whitelist-оверлей и `mo purge --yes` вместо драйвера меню: `mo purge` пропускает защищённые артефакты. Проверено сквозным тестом на Mole 1.59.1 в песочнице `$HOME`.
2. **Навигация** по референсам CleanMyMac: панель иконок с карточками-подсказками вместо боковой панели с подписями; круглая кнопка действия живёт в дочернем окне над нижним краем окна.
3. **«Умный уход»** запускает четыре пробных прогона параллельно (все только читают), поэтому сканирование длится столько, сколько самый медленный.
4. **Расписание** («Безопасность») работает от таймера внутри Nora, пока она открыта или в строке меню; отдельного помощника launchd нет.
5. **Права администратора** запрашивает диалог пароля osascript как `SUDO_ASKPASS`; Touch ID работает после `mo touchid enable`.
6. **Режим энергии** выполняется как `sudo -A /usr/bin/pmset`, потому что `pmset -a` сам требует root. Соответствие: `powermode` 0 Авто, 1 Тихо, 2 Мощно.
7. **Ещё не сделано:** MCP-сервер только для чтения, палитра команд ⌘K, аудит расширений браузеров и профилей конфигурации, выбор личных данных (`D`) для программ.
8. **«Анализ диска»** показывает папки пузырями рядом со списком папок, вместо колец и treemap.
9. **Команды под действиями** видны, только когда в Настройках → Mole → Команды это включено (по умолчанию выключено); консоль показывает их всегда, а команды установки и обновления при первом запуске видны всегда.
10. **Меню-бар:** графику и вентилятор перенесли в «Состояние системы», чтобы освободить место для блока памяти только для просмотра; четыре плитки выбираются в Настройках.

## 10. Риски

- **Дрейф CLI:** текстовые парсеры ломаются с новыми версиями. Защита — проверка возможностей, эталонные фикстуры, CI с текущим Mole.
- **PTY-драйвер** хрупкий. Защита — сверка экрана перед подтверждением и запасной встроенный терминал.
- **Конкуренты:** mole.fit (официальный, $19) и Burrow (бесплатный, MIT). Наше отличие — честный выбор, неоновый 3D-дизайн и полное покрытие CLI без собственного движка.
- **Разрешения:** полный доступ к диску, нотаризация, askpass-хелпер (подписанный, минимальный) и доступ к автоматизации System Events (`NSAppleEventsUsageDescription`): каждое настоящее `mo uninstall` убирает элементы входа через AppleScript, поэтому macOS спросит разрешение при первом удалении.
- **Личные данные программ (`D`):** `mo uninstall <имя>` не предлагает клавиши `D`, она есть только в интерактивном TUI. Переключатель «личные данные» в «Программах» пока без механизма — задача M2. Сквозные тесты ещё не покрывают обычный путь через Корзину и шаг с System Events, потому что идут с `MOLE_TEST_NO_AUTH=1 --permanent`.
