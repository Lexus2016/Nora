## Safe screenshot / UI CI plan
Existing DEBUG -NoraModule / -NoraAutoScan / -NoraSpaceMapRoot / -NoraShowPopover / -NoraShowSettings / -NoraSettingsTab only select views or trigger real operations. They are not isolation. Default AppDelegate startup writes askpass/recovery files, starts updater, reaps scanners, locates Mole, resumes Downloads watch, starts schedule; view tasks can still run independently.
Use `NORA_UNIT_TESTING=1` plus a DEBUG-only injected synthetic model (`isVisualSnapshot`) and guards on view startup tasks. Render fixture-only start/review/empty/scanning/done/failure states; never tap real action closures. Require fixture paths and in-memory payloads. Native XCTest PNG attachments in xcresult should cover every module and four Settings tabs in en/uk/ru at minimum supported 1040×620 and default 1240×800. Pixel presence only proves rendering: inspect attachments for clipping, contrast, hierarchy, localized truncation, orb overlap, long paths/error text, stale/partial labels. Add a separately isolated XCUITest target if keyboard/VoiceOver event coverage is needed. Do not describe snapshots as end-to-end cleanup verification.
